# value-registry

Two governance instruments that share one data model:

- **AI Opportunity Value Model** — weighted scoring against a
  YAML-declared rubric, readiness multipliers, ROI/NPV, and a staged
  lifecycle with machine-checkable gates.
- **Model Registry & TPRM schema** — a model inventory with capability
  tier, provenance, approval state, review cadence, and per-dimension
  risk scoring whose **confidence values are part of the output**.

## The differentiating feature: evidence-classed figures

Every number in this system carries three things:

```yaml
annual_benefit: { value: 240000, evidence: modeled, confidence: 0.5, unit: USD }
```

- **`evidence`** — how the number was obtained: `documented` (traceable
  to a source record), `estimated` (derived by a person from partial
  data), or `modeled` (produced by an assumption-bearing model).
- **`confidence`** — declared certainty in [0, 1].

The engine **refuses a bare number** (`UnclassifiedFigureError`), and
reports render the class and confidence beside every figure:

```text
| Synthetic Demand Forecasting (OPP-001) | pilot | 3.10 [modeled, conf 0.66] | 254,061 USD [modeled, conf 0.50] | ...
```

Aggregation cannot launder provenance: a weighted score inherits the
*weakest* evidence class among its inputs, and derived quantities
(NPV, ROI, payback) carry the *minimum* input confidence. One modeled
input makes the whole claim modeled — which is exactly what an honest
value report should say. Lifecycle gates can require it: the example
rubric's `scale` gate sets `forbid_modeled_financials: true`, so an
opportunity cannot pass into scaled operation on modeled money.

## Quickstart (< 60 seconds)

```bash
cd packages/value-registry
pip install -e .
make demo
```

`make demo` scores the synthetic example portfolio, regenerates the
fixed-seed synthetic model catalog, and renders both markdown reports
into `out/`.

Or call the CLI directly:

```bash
value-registry score --rubric examples/rubric.yaml --portfolio examples/portfolio.yaml --out out/portfolio_report.md
value-registry generate-catalog --out out/catalog.yaml          # seed=42, count=140
value-registry registry-report --catalog data/catalog.yaml --out out/registry_report.md
```

## The synthetic catalog

`data/catalog.yaml` ships ~140 **fictional** model inventory entries,
generated by `value-registry generate-catalog` with a fixed seed —
same seed, same catalog, byte for byte. No real vendors or models are
described, and the schema has **no concept of a country**: origin risk
exists only as the generic boolean `origin_risk_flag`
(the *geopolitical-origin risk flag*), by design.

## Configuration is declared, not coded

Scoring dimensions, weights, readiness multipliers, lifecycle stages,
and gate thresholds all live in the rubric YAML
([examples/rubric.yaml](examples/rubric.yaml)). The engine validates —
weights must sum to 1.0, stages and readiness levels must exist — but
invents nothing.
